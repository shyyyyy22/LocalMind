## 推荐顺序与指导

按"从简单到复杂、每步都有独立产出"的原则：

### 第 1 步：搜索模块（推荐先做）

**为什么先做**：搜索是 V0.1 的闭环终点——没有搜索，索引就没有意义；纯 Python + SQL，不引入新框架，适合过渡。

**要学的知识：**

- SQL 的 `WHERE`、`LIKE`、范围条件、`ORDER BY`、`LIMIT`
- SQLAlchemy 的 `select()` / `filter()` / `like()`（watcher 里已用过 `select`，可对照）

**要做的功能**（对应设计文档第 27 节）：

- 按文件名模糊搜索
- 按扩展名过滤（如 `.pdf`）
- 按路径过滤（如 `D:/学习`）
- 按修改时间过滤（区间）
- 按文件大小过滤（区间，如 `>1MB`）
- 多条件可组合

**验收标准**：命令行入口能查到自己电脑上的真实文件。

### 第 2 步：pytest 测试

**要学的知识**：`pytest.fixture`、`tmp_path`（临时目录）、测试数据库隔离。

**关键思考题**：`models.py` 里 engine 写死了 `sqlite:///localmind.db`，测试时怎么避免污染真实数据库？（这是写测试时第一个要解决的设计问题）

### 第 3 步：FastAPI + 基础 Web UI

**要学的知识**：路由（GET/POST）、参数解析、返回 JSON、最简单 HTML 页面调用接口。

**要做的**：页面输入关键词 → 调用搜索 API → 表格展示结果。

### 第 4 步：收尾

- 硬编码路径改为配置（文档目录结构中的 `app/core/config.py`）
- `git init` 提交（顺便学 Git）

## 提前埋下的问题（先别改，做的时候自然会遇到）

1. `scanner.py` 和 `watcher.py` 有重复的"建 File 记录"逻辑——做测试时会逼你思考怎么消除。
2. `files` 表缺设计文档里的 `mime_type` 和 `status` 字段——现在补或做搜索时再决定是否必要。
